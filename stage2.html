STAGE 2

CPUとレジスタ

計算の前に、まず運ぶ
🎯 ミッション
CPU がメモリのデータを計算するまでの流れ（LOAD → 計算 → STORE）と、メモリが遅いことの意味を説明できるようになろう。3＋4 のプログラムを最後まで動かし、確認クイズに全問正解すれば合格。
未達成
ねこ博士
前のステージで、メモリは番地付きの箱の列だと分かった。今日は、CPU がその箱の中身でどうやって計算するかを見よう。CPU は、メモリの中の数を、その場で足し算できると思う？
うさ美
あ、思い出しました。『論理回路CPUクエスト』の最後で、小さな CPU を動かしました。足し算をする ALU の入口は、CPU の中のレジスタという箱につながっていて、メモリの数はまず LOAD でレジスタに読み込んでいました。計算したら STORE でメモリに書き戻す。
ねこ博士
そう。CPU の計算回路（ALU）につながっているのは、CPU の中にある数十個のレジスタだけなんだ。メモリの中身を計算したければ、必ず「運んで、計算して、戻す」。番地 6 の数と番地 7 の数を足して番地 5 にしまうなら、命令はこうなる。
LOAD 6　：番地6 の値をレジスタ A に読み込む ADD 7　：番地7 の値を読み、A に足す（ALU が足し算） STORE 5：A の値を番地5 に書き込む
うさ美
そもそも、どうしてメモリの中で直接計算しないんですか？ 運ぶ手間がもったいない気がします。
ねこ博士
メモリは CPU とは別の部品だからなんだ。パソコンを開けると、CPU とメモリは別々の板に載っていて、細い配線でつながっている。80億個の箱の1つ1つに計算回路を付けるわけにはいかないから、計算は CPU にまとめて、データを運ぶ。そして、この「運ぶ」が、とても遅い。
うさ美
どのくらいですか？
ねこ博士
CPU の合図（クロック）の1拍は、3GHz なら約0.3ナノ秒（ナノ秒は10億分の1秒）。それに対して、メモリに番地を伝えて中身が返ってくるまでには、およそ100ナノ秒かかる。
うさ美
100 ÷ 0.3 で……約300拍。足し算は1拍でできるのに、数を1つ取ってくるのに300拍待つんですか。
ねこ博士
そういうこと。しかも命令そのものもメモリに入っているから、命令を取り出すたびにも待ち時間がかかる。

※ 模型では分かりやすく、メモリの読み書き1回を100拍、足し算を1拍として数える。

うさ美
計算そのものはほんの一瞬で、時間のほとんどは「待つ」ことに使われている……。CPU がいくら速くなっても、メモリが遅いと意味がないですね。
ねこ博士
その問題は「メモリの壁」と呼ばれていて、コンピュータの設計者がずっと悩んできたことなんだ。だから、記憶の置き場所は、速さと大きさの違う何段階かに分けて使う。
レジスタ：約0.3ナノ秒、数百バイト（CPU の中） キャッシュ：約1〜10ナノ秒、数十KB〜数十MB（CPU の中。次のステージ） メモリ（RAM）：約100ナノ秒、数GB〜数十GB ストレージ（SSD）：約10万ナノ秒（0.1ミリ秒）、数百GB〜数TB。電源を切っても消えない
うさ美
机の上と、引き出しと、部屋の本棚と、図書館みたいですね。机の上はすぐ手が届くけど狭い。図書館はなんでもあるけど、行って帰るのに時間がかかる。
ねこ博士
いいたとえだね。よく使うものほど手元に置く、という考え方が、次のステージのキャッシュにつながる。
うさ美
ところで、プログラムで score = score + 10 と書いたら、どの番地を LOAD するかは誰が決めるんですか？ 書いた人は番地を書いていません。
ねこ博士
プログラムを CPU の命令に翻訳するコンパイラというプログラムが決めている。変数 score を「番地 0x1000 の4バイト」のように割り当てて、score を使う場所を、その番地への LOAD や STORE に書き換えるんだ。よく使う変数は、メモリに置かずにレジスタに置いたままにして、往復を減らすこともある。
うさ美
名前は人間のためのもので、CPU から見ると番地だけなんですね。
ねこ博士
そう。では、その番地を、コンパイラはどういう規則で決めているのか。それがこの旅の残りの大部分になる。その前に、往復の遅さを和らげる工夫、キャッシュを見ておこう。

確認クイズ

Q1. CPU がメモリにある2つの数を足すとき、正しい流れは？

正解！ ALU につながっているのはレジスタだけ。メモリの数は運んでから計算し、結果を戻す。

Q2. 3GHz の CPU にとって、メモリから1つ読む約100ナノ秒は、およそ何拍分？

正解！ 1拍は約0.3ナノ秒。100 ÷ 0.3 ≒ 300。足し算1回は1拍なので、待ち時間のほうがずっと長い。

Q3. 変数 score がメモリのどの番地に置かれるかを決めているのは？

正解！ 名前は人間のためのもの。コンパイラが番地やレジスタを割り当て、変数を使う場所を LOAD・STORE に書き換える。
