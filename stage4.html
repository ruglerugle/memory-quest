STAGE 4

スタック

関数を呼ぶと板が積まれる
🎯 ミッション
関数呼び出しでスタックに何が積まれ、いつ消えるかを説明できるようになろう。関数を呼ぶプログラムを最後まで1行ずつ進め、確認クイズに全問正解すれば合格。
未達成
ねこ博士
ここからは、プログラムのデータがメモリのどこに置かれるかを見ていく。最初は関数だ。関数は、決まった仕事をまとめて名前を付けたもので、呼ぶと仕事をして、答えを返して、呼んだところへ戻ってくる。たとえば、x を受け取って x×x を返す square という関数を考えよう。
int square(int x) { int y = x * x; return y; } int main(void) { int a = 3; int b = square(a); int c = b + 1; } int は4バイトの整数。main はプログラムが最初に動かす関数
うさ美
square の中の x と y は、どこにしまわれるんですか？ 決まった番地を割り当てておくんですか？
ねこ博士
決まった番地にすると困ることがあるんだ。square が自分自身を呼ぶような関数だったら、1回目の x と2回目の x を、同時に覚えておかなければならない。だから、関数の変数は呼ばれるたびに新しく場所を用意して、終わったら片付ける。そのための場所がスタックだ。
うさ美
スタック……「積み重ね」という意味ですよね。
ねこ博士
そう。皿を積むように、上に積んで、上から取る。最後に積んだものを最初に取り出すので、Last In First Out、略して LIFO と呼ぶ。関数を呼ぶたびに、その関数のための板を1枚積む。この板をスタックフレームと呼ぶ。板には、その関数のローカル変数（関数の中だけで使う変数）と、もう1つ大事なものが書かれる。
うさ美
もう1つ？
ねこ博士
「仕事が終わったらどこへ戻ればいいか」だ。square は main から呼ばれることもあれば、ほかの関数から呼ばれることもある。だから、呼ぶときに「呼んだ場所の次の命令の番地」を板に書いておく。これを戻り先（リターンアドレス）と呼ぶ。
関数を呼ぶ：板（スタックフレーム）を1枚積む。戻り先・引数のコピー・ローカル変数の場所 関数が終わる（return）：答えを渡し、板を丸ごと取り除いて、戻り先へ戻る
うさ美
square が終わったら、x と y は板ごと消えてしまうんですね。だから、関数の中で作った変数は、関数の外では使えない。
ねこ博士
そう。そして、片付けるのに何もしなくていいのがスタックのいいところだ。CPU は「いまの一番上はここ」という番地を覚えておく専用のレジスタ（スタックポインタ）を持っていて、板を積むのも取るのも、その番地を板の大きさだけ動かすだけで済む。
うさ美
引数の x は、a そのものではなくコピーなんですか？
ねこ博士
C言語では、引数には値のコピーが渡される。だから square の中で x を書き換えても、main の a は変わらない。もし関数の中から呼んだ側の変数を書き換えたいときは、変数の番地を渡す必要がある。それが STAGE6 のポインタの話につながる。
うさ美
スタックの大きさに限りはあるんですか？ 関数が関数を呼んで、それがまた関数を呼んで……と深くなると、板がどんどん積まれます。
ねこ博士
限りはある。プログラムごとに、スタックに使える大きさが決まっている（数MB程度が多い）。関数が自分自身を呼び続けて止まらないような間違いがあると、板が積まれ続けて、決められた大きさを超える。これをスタックオーバーフロー（スタックあふれ）と呼び、プログラムは強制的に止められる。
うさ美
板の大きさは、いつ決まるんですか？
ねこ博士
関数の中のローカル変数の大きさは、プログラムを翻訳する時点で分かっている。だから、コンパイラが「この関数の板は何バイト」と決めておける。逆に言うと、実行してみるまで大きさが分からないものや、関数が終わったあとも残しておきたいものは、スタックには置けない。それを置くのが、次のヒープだ。

確認クイズ

Q1. スタックの「LIFO」の意味は？

正解！ Last In First Out。皿の山のように、上に積んで上から取る。関数は呼んだ順の逆に終わるので、この形がぴったり合う。

Q2. 関数を呼んだときにスタックフレームに書かれる「戻り先」とは？

正解！ 同じ関数がいろいろな場所から呼ばれるので、どこへ戻るかを呼ぶたびに書いておく。

Q3. 関数の中のローカル変数を、関数が終わったあとに使えない理由は？

正解！ 板を取り除くのはスタックポインタを動かすだけ。場所は次の関数の板として再利用される。
