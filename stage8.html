STAGE 8

メモリの配置

コード・データ・ヒープ・スタック
🎯 ミッション
プログラムのメモリの区画と、そこに置かれるものを説明できるようになろう。7つのものを正しい区画に振り分け、確認クイズに全問正解すれば合格。
未達成
ねこ博士
ここまでで、スタックとヒープを見てきた。でも、プログラムがメモリの中で使う場所は、それだけではない。今日はプログラム全体のメモリの地図を描こう。まず、プログラムの命令そのものは、どこにあると思う？
うさ美
『論理回路CPUクエスト』で、命令もメモリに入っていて、PC が指す番地から取り出していました。だから、命令もメモリのどこかの区画にあるはずです。
ねこ博士
そう。命令が置かれる区画をコード（テキストとも呼ぶ）と言う。プログラムを起動すると、ストレージにあるプログラムのファイルから、命令がこの区画に読み込まれる。次に、関数の外で宣言した変数、たとえば int count = 10; はどうだろう。
うさ美
関数の外の変数は、関数が終わっても消えてほしくない。でもスタックは関数ごとに片付くし、ヒープは malloc で借りるものだから……どちらでもないですね。
ねこ博士
そう。関数の外の変数は、プログラムが動いているあいだずっと同じ場所にある。大きさも翻訳のときに決まっている。だから、コードのすぐ近くに専用の区画を取る。最初の値が決まっているものは初期化済みデータの区画、値を書いていないもの（int total;）は未初期化データの区画（BSS と呼ぶ）に置く。
うさ美
わざわざ分ける理由は？
ねこ博士
未初期化データは「起動したら全部 0 にする」と決まっているので、プログラムのファイルには「何バイト分あるか」だけ書いておけばいい。100万個の 0 をファイルにしまう必要がない。初期化済みデータは、値をファイルに書いておく必要がある。
うさ美
プログラムに書いた "hello" みたいな文字列はどうなるんですか？
ねこ博士
文字列そのものは、プログラムの中に書かれた決まった文字で、書き換えることは想定していない。だから読み取り専用データの区画に置く。ここは書き込もうとすると CPU と OS が止めるようになっている。コードの区画も同じく読み取り専用だ。
うさ美
書き換えられないように守っているんですね。
ねこ博士
そう。命令が書き換えられたら、プログラムが乗っ取られてしまう。それを防ぐために、区画ごとに「読める」「書ける」「命令として実行できる」の許可を分けている（そのしくみは STAGE10 で見る）。全体をまとめるとこうなる。
コード：機械語の命令。読み取り・実行のみ。起動時にファイルから読み込む 読み取り専用データ：文字列など書き換えない決まった値 初期化済みデータ：関数の外の変数で、最初の値を書いたもの 未初期化データ（BSS）：関数の外の変数で、値を書いていないもの。起動時に 0 ヒープ：malloc で借りる場所。借りるたびに広がる スタック：関数のローカル変数と戻り先。呼ぶたびに伸びる
うさ美
ヒープとスタックは、どちらも実行中に大きさが変わりますよね。ぶつかったりしないんですか？
ねこ博士
多くの環境では、ヒープは小さい番地から大きい番地へ、スタックは大きい番地から小さい番地へと、向かい合って伸びるように配置する。間に広い空きを取っておけば、どちらがどれだけ伸びるか前もって分からなくても、空きを無駄なく使える。
うさ美
1本のメモリの両端から、それぞれ伸ばしていくんですね。
ねこ博士
区画の分け方は、「いつ大きさが決まるか」と「いつまで残るか」で整理するといい。
翻訳時に決まり、ずっと残る：コード・読み取り専用データ・初期化済みデータ・未初期化データ 実行中に決まり、返すまで残る：ヒープ 実行中に決まり、関数が終わると消える：スタック
うさ美
変数を書いた場所（関数の中か外か）と、malloc を使うかどうかで、置かれる区画が決まるんですね。最初の「名前で書いた変数が、メモリのどこに、いつ置かれるのか」という問題の答えが、これで揃いました。
ねこ博士
そう。残っているのは、「それを間違えると何が起きるのか」だ。次のステージで見よう。

確認クイズ

Q1. 関数の外で int total;（値を書いていない）と宣言した変数が置かれる区画は？

正解！ 関数の外の変数はずっと残るのでデータの区画。値を書いていないものは BSS に置かれ、起動時に 0 になる。

Q2. 文字列 "hello" を読み取り専用の区画に置く理由は？

正解！ 書き換えないものは書き込み禁止にしておけば、間違って壊すことも、悪用されることも防げる。

Q3. ヒープとスタックを、メモリの両端から向かい合うように伸ばす理由は？

正解！ 片方が多く使い、もう片方が少ししか使わなくても、間の空きを共有できる。
